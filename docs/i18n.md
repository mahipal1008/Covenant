# i18n & RTL audit

Session 5 §1. Tracks the readiness of `apps/web` for additional
locales beyond the default `en`/`es` bundles.

## Implementation

- Bundles live at `apps/web/src/i18n/messages/<locale>.json`. Add a
  new file and import it from `apps/web/src/i18n/index.ts`.
- `getMessages(locale)` and `t(key, locale)` provide a dotted-path
  lookup with English fallback.
- `apps/web/src/i18n/format.ts` exports `formatDate`, `formatNumber`,
  `formatCurrency`, `formatRelative` — wrappers around `Intl.*` that
  default to the active locale.
- `isRtl(locale)` returns true for `ar`, `he`, `fa`. The root layout
  reads this and sets `<html dir="rtl">` when needed.
- `next-intl` is intentionally **not** wired yet — once the routing
  strategy (sub-path vs. domain) is decided we can swap the loader
  without touching call sites.

## RTL CSS audit checklist

When introducing an RTL locale, verify each of the following:

- [ ] No raw `left`/`right` properties — use Tailwind's logical
  `start`/`end` variants (`ms-*`, `me-*`, `ps-*`, `pe-*`).
- [ ] Iconography that conveys direction (arrows, carets) is mirrored
  via `rtl:rotate-180` or paired with localized labels.
- [ ] Numerals stay LTR inside RTL blocks (use `<bdi>` or
  `unicode-bidi: isolate` when mixing).
- [ ] Form inputs keep their text direction inherited from
  `<html dir>`; do not hard-code `dir="ltr"`.
- [ ] Tables: `text-start`/`text-end` instead of `text-left`/`right`.
- [ ] Tooltip and popover anchors use logical placement (`start`,
  `end`) so they flip automatically.

## Locale-specific number formatting

`Intl.NumberFormat` already handles digit shaping (e.g. Arabic-Indic
digits) when the locale requests it. Pass `useGrouping: false` for
identifiers and dates to keep them locale-stable.

## Adding a new locale

1. Copy `en.json` to `<locale>.json` and translate.
2. Extend the `Locale` union in `apps/web/src/i18n/index.ts`.
3. Add a row to the RTL audit checklist above and tick each item.
4. Add a Storybook story rendered with the new locale to catch
   layout regressions.
